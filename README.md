# Стройка

Проекты квартир: планировки, варианты отделки, 3D и проектная документация (электрика, сантехника и водопровод) — по всей квартире и по каждой комнате. Сайт собирается на своей машине в папку `docs/` и публикуется через GitHub Pages без GitHub Actions.

Сайт: https://kprokopchik.github.io/stroika/ (после включения Pages, см. ниже).

## Как устроен сайт

```
Все объекты
└── Квартира 95,7 м²                 описание, ссылки застройщика, варианты, сравнение, план застройщика
    └── Вариант 1                    план, заметки, комнаты, разделы, рендеры
        ├── План квартиры            план с зумом, наложение плана застройщика
        ├── 3D-модель                крутится вокруг вертикальной оси, зум щипком и колесом
        ├── Комнаты / Детская 1      план комнаты с зумом, заметки, рендеры
        ├── Электрика                план раздела по квартире
        │   ├── Распределительный щит
        │   └── Детская 1 …          раздел по комнате
        └── Сантехника и водопровод
            ├── Узел ввода и коллектор
            └── Детская 1 …
```

На каждой странице есть хлебные крошки и меню-дерево: на компьютере оно слева, на телефоне открывается кнопкой «Меню». Планы открываются в просмотрщике с зумом: щипок двумя пальцами, перетаскивание, двойной тап, колесо мыши, кнопка «На весь экран».

## Папки

```
build.py                 сборка: python3 build.py → docs/
tools/
  plan_svg.py            чертёж плана в SVG (стены, двери, окна, мебель, размеры)
  site_gen.py            генератор страниц
  scene3d.py             3D-модель и рендеры в Blender (по желанию)
  post3d.py              сжатие рендеров и подписи на виде сверху
  eng_svg.py             условные обозначения инженерных разделов
  make_pdf.py, pdf.js    листы для печати и PDF через Chromium
site_assets/             стили и скрипты сайта (меню, зум планов, 3D)
projects/<объект>/
  object.py              название, описание, ссылки застройщика, комнаты, разделы
  layout.py              стены, окна, двери и расстановка по вариантам (координаты в см)
  content.py             тексты: описания вариантов, заметки по комнатам, подписи рендеров, сравнение
  scene_cfg.py           камеры и свет для 3D
  plan.jpg               план застройщика
  eng.py                 инженерные разделы: точки, трассы, щит, схемы
  renders/  models/      готовые рендеры (.jpg) и 3D-модели (.glb)
  pdf/                   PDF для печати (tools/make_pdf.py)
docs/                    собранный сайт, его раздаёт GitHub Pages
```

## Сборка

Нужен только Python 3.10 или новее, без сторонних пакетов.

```bash
python3 build.py         # пересобирает docs/ целиком
git add -A && git commit -m "Обновил сайт" && git push
```

Посмотреть локально до публикации:

```bash
cd docs && python3 -m http.server 8000   # открыть http://localhost:8000
```

## Публикация на GitHub Pages

Один раз в настройках репозитория: **Settings → Pages → Build and deployment → Source: Deploy from a branch**, ветка `main`, папка `/docs`, Save. Через минуту сайт появится по адресу выше. Дальше достаточно пушить пересобранную папку `docs/`. Свои workflow не нужны. В `docs/` лежит `.nojekyll`, поэтому GitHub раздаёт файлы как есть, без Jekyll.

## PDF для печати (по желанию)

Планы вариантов на A3 в масштабе 1:50, разделы (план A3 и пояснения A4), щит, ИБП, коллектор, шкаф на A4 и альбом варианта со всеми листами. На сайте у этих страниц появляется кнопка «PDF».

Нужны Node.js и Playwright с Chromium (один раз: `npm i playwright && npx playwright install chromium`).

```bash
python3 tools/make_pdf.py          # все объекты → projects/<объект>/pdf/
python3 tools/make_pdf.py kvartira-95
python3 build.py                   # копирует PDF в docs/ и ставит ссылки
```

PDF пересобираем после правок планов или разделов: сами они не обновляются.

## 3D-рендеры и модели (по желанию)

Нужен Blender как модуль Python. Он работает на Python 3.11:

```bash
uv venv -p 3.11 .venv-3d && uv pip install --python .venv-3d/bin/python bpy==4.2.0 numpy
P=projects/kvartira-95
# модель для страницы «3D-модель»
.venv-3d/bin/python tools/scene3d.py --project $P --variant 1 --export $P/models/v1.glb
# рендеры: все камеры варианта из scene_cfg.py (на 4 ядрах ~2–3 минуты на кадр)
.venv-3d/bin/python tools/scene3d.py --project $P --variant 1 --views all --out tmp/renders --samples 48 --res 1200x800
python3 tools/post3d.py tmp/renders $P/renders $P
python3 build.py
```

## Новый объект

1. Скопируйте `projects/kvartira-95` в `projects/<новое-имя>` и замените `plan.jpg`.
2. В `object.py` поменяйте `slug` (имя папки), название, описание, ссылки застройщика, комнаты.
3. В `layout.py` обведите стены и окна по новому плану (сантиметры, x вправо, y вниз), расставьте мебель по вариантам.
4. В `content.py` напишите тексты вариантов. Советы «На что обратить внимание» — в `TIPS`: `common` для страницы варианта и `rooms[вариант][комната]` для страниц комнат. `python3 build.py`.

## Разделы проекта

Разделы перечислены в `SECTIONS` в `object.py`: у каждого есть страница по всей квартире, страницы по комнатам и дополнительные страницы, например щит или коллектор.

Содержимое разделов лежит в необязательном `projects/<объект>/eng.py`. Функция `build(n)` возвращает данные для варианта `n`: слои поверх плана (SVG), легенду, таблицы, схемы, блоки по комнатам и дополнительные страницы. Условные обозначения рисует `tools/eng_svg.py`. Если для варианта данных нет, раздел помечен «в работе», а на плане только бледная расстановка.

Сейчас для квартиры 95,7 м² проработан вариант 1: электрика с линией ИБП, водопровод и канализация, слаботочка.

## Две сессии в одном репозитории

- Общий код (`tools/`, `site_assets/`) меняем так, чтобы старые проекты собирались как раньше: новые параметры необязательные.
- Перед пушем в `main`: `git fetch origin main && git merge origin/main`, потом `python3 build.py`, потом push.
- Конфликты в `docs/` руками не разбираем: берём любую сторону и пересобираем `python3 build.py`.
